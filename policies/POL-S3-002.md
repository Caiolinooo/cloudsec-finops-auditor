# [POL-S3-002] Versioning + Lifecycle to Glacier after 90 days

- **Severity:** MEDIUM
- **Framework:** FinOps 4.2 · CIS AWS 2.1.3 (versioning)
- **Domain:** S3 / FinOps / Retention

## Clause

Non-hot object stores (analytics, logs, backups, compliance archives) MUST:

1. Enable S3 Versioning
2. Attach a lifecycle configuration that transitions current objects to
   `GLACIER` or `DEEP_ARCHIVE` after **90 days**
3. Expire noncurrent versions after a documented retention window (default 365 days)

Leaving 18+ months of raw logs or analytics extracts in S3 Standard without a
lifecycle rule is a FinOps 4.2 waste finding.

## Rationale

S3 Standard is priced for frequent access. Cold telemetry and historical extracts
should move to Glacier-class storage to cap monthly spend while preserving
recoverability via versioning.

## Remediation

1. `PutBucketVersioning` = Enabled
2. Add lifecycle rule `transition-90d-glacier` (prefix `*` or documented prefixes)
3. Tag the bucket `finops:tier=cold` and track cost in the monthly FinOps review
4. Validate with Storage Lens: % of bytes in Standard vs Glacier

## Cost note

Typical 40–70% storage reduction for log/archive prefixes after the first
transition cycle; restore costs apply for expedited Glacier access.
