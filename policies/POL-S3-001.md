# [POL-S3-001] Block Public Access for customer-data buckets

- **Severity:** CRITICAL
- **Framework:** SOC 2 CC6.1 · CIS AWS Foundations 2.1.5
- **Domain:** S3 / Data protection

## Clause

Buckets that store customer data, PII, PCI, or regulated archives MUST enable
Amazon S3 Block Public Access at both the account and bucket level. Public ACLs
(`AllUsers`, `AuthenticatedUsers`) and wildcard `Principal: "*"` bucket policies
are forbidden on `customer-data*` and equivalent sensitivity labels.

A bucket is non-compliant when any of the following is true:

- Block Public Access is disabled or only partially applied
- The bucket ACL grants `READ`, `WRITE`, or `FULL_CONTROL` to `AllUsers`
- A bucket policy allows `s3:GetObject` or `s3:ListBucket` to `"*"`

## Rationale

Public object ACLs are a recurring breach pattern (open backup dumps, leaked
exports). SOC 2 CC6.1 requires logical access controls that prevent unauthorized
external disclosure of customer information.

## Remediation

1. Enable all four Block Public Access settings on the account and the bucket
2. Remove public ACLs and convert remaining access to least-privilege bucket policies
3. Add a deny statement for `s3:PutBucketAcl` / public ACL writes
4. Turn on Access Analyzer and AWS Config rule `s3-bucket-public-read-prohibited`

## Evidence

CloudTrail `PutBucketAcl` / `PutBucketPolicy`, Config findings, Access Analyzer
external access findings.
